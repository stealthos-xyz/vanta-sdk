# Security policy

Use the currently signed release and the corresponding registered configuration. Development candidates do not provide deployment or custody authorization. The release-specific [audit findings and scope](docs/audit/README.md) distinguish internal engineering evidence from independent assurance.

## Reporting vulnerabilities

Report security findings privately through the repository's private vulnerability reporting feature when enabled, or your established StealthOS engineering/partner contact. Do not open a public issue with exploitable details.

Include the affected SDK version, network, generation, component, minimal reproducible behavior using disposable credentials, and expected versus actual result. Do not include recovery phrases, keys, witness inputs, private notes, bearer tokens, or raw private journals. Coordinate public disclosure with StealthOS.

For ordinary integration issues use [GitHub issues](https://github.com/stealthos-xyz/vanta-sdk/issues). No response-time SLA or bounty is implied by this policy.
