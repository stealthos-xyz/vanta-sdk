# Wallet balances, recovery and continuity

Create or restore a private wallet with the selected connected account. Use the recovery callback to display the phrase only in trusted local UI, require confirmation of safe offline storage and clear it afterward. Do not store a plaintext password/phrase, share local keys with a backend, or send private transaction identifiers to telemetry. An encrypted backup is not a replacement for safe phrase custody.

Render getCachedBalance() immediately if present, explicitly as display-only. recoverNotes() returns a generation, canonical block/hash, received transactions and pools. Each pool has assetDecimals, spendableBalanceUnits, spentBalanceUnits, spendableCount, spentCount, verifiedEmpty; optional unreservedBalanceUnits, availableBalanceUnits, projectedBalanceUnits and pendingChangeBalanceUnits distinguish reservations and expected change. Show spendable and pending separately; never substitute projected for verified spendable. If recovery fails, show unavailable/stale rather than a verified zero. Do not use cached balances for spend authorization.

Wallet state is account/network scoped; SDK locks on account, chain, disconnect or pagehide. Clear the UI, discard quote closures and dispose the old client. Reopen using the correct provider and configuration. Recover pending state from journal lists, not by replaying a request. On asset switches, invalidate old quote/prepared UI and preserve history using historyAsset where supported.

exportRecoveryBackup() returns encrypted JSON text. Save locally as a file at the user's explicit request. On the new device restore the same authenticated account/network with the phrase, then pass a selected Blob to importRecoveryBackup(file). Reconcile canonical state. Never upload the backup automatically or print its contents.

Historical generation access is exposed via /recovery: createVantaFamilyGenerationWallet supports generations(), openWithdrawal(selection), openDeposit(selection), dispose(). The generation wallet requires a trusted local wallet controller, generation-scoped store, independent providers and trusted approval/submission callbacks. Integrate that advanced path only with the preserved historical artifact catalog; do not substitute the current generation. See [generation types](../packages/vanta-sdk/fresh/family-wallet-generations.d.mts). If the partner needs independent historical exit UI, coordinate its testing with StealthOS before launch.
